# Implementation Plan: Akuvox Local HTTP API Library

**Branch**: `001-akuvox-http-library` | **Date**: 2026-02-13 |
**Spec**: [spec.md](spec.md)
**Input**: Feature specification from
`/specs/001-akuvox-http-library/spec.md`

## Summary

Build an async-only Python library (`pylocal-akuvox`) that wraps the
Akuvox device local HTTP API. The library provides a single `AkuvoxDevice`
object for connecting to Akuvox intercoms and access controllers on the
LAN, managing users/PINs, controlling relays, querying status, managing
schedules, and retrieving logs. It targets Home Assistant integration
with minimal dependencies (aiohttp only). The Akuvox API uses JSON
payloads over HTTP with Basic/Digest/AllowList authentication.

## Phases

### Phase 1: Core Connection & Device Info (US1 + US2)

Establish HTTP client, auth config, device info retrieval, and status
queries. This phase creates the foundational `AkuvoxDevice` class and
the exception hierarchy.

### Phase 2: User & PIN Management (US3 — MVP Target)

Implement CRUD operations for local users including PIN programming.
This is the primary MVP deliverable.

### Phase 3: Relay Control & Logs (US4 + US6)

Add relay activation and call/door log retrieval. These are read/write
operations that build on the HTTP client from Phase 1.

### Phase 4: Schedules & Auth Methods (US5 + US7)

Add schedule CRUD and explicit Basic/Digest auth support beyond
the default AllowList mode.
